# 界面层规格（一致性与分层约束）

> 本文是 `ui` / `shell` / `design` / `login` / `timetable` 的唯一结构真源。
> 与 `docs/specs/网络层.md §2` 是同一种写法：**目录树 + 分层职责 + 可测性**。
> 改包结构前先读本文；改完更新本文。

## 1 为什么需要这份规格

`net/` 有 `网络层.md §2` 管着，`skin/` 有 ADR-0003~0006 管着，唯独曾经占全部代码
62% 的界面层**没有任何结构约束**，结果长成一个：

- `ui/MainShell.kt` 单文件 1,392 行、单个 Composable 函数 1,129 行、36 个状态、16 个 `LaunchedEffect`；
- 纯数据模型（`CourseEntry`）跑校验要 `require` 依赖 `logic` 的常量；
- 业务数据读写（教师/地点/周次/考勤/备注 + DataStore 防抖落盘）全部堆在导航壳里，0 测试；
- 皮肤数据源 `skin/` 反向 import 表现层的 `ui.theme.NongyuColors`。

## 2 当前目录树

```text
app/src/main/java/com/nongyu/appplus/
├── MainActivity.kt              入口；皮肤在 setContent 前同步解析（ADR-0006）
├── NongyuApp.kt                 根组件：when(会话状态) 在 MainShell / 登录中心之间切换
│
├── design/                      设计层（skin 与各 UI 的公共下游，不含业务）
│   ├── NongyuColors.kt          色板 token（纯 @Immutable data class，零 Composable）
│   ├── Theme.kt                 主题与 CompositionLocal 下发
│   ├── UiScale.kt               屏宽自适应基准（411dp）—— **全工程唯一出处**
│   └── ModalScrim.kt            通用遮罩
│
├── icon/                        自绘图标几何与描边（NavIconGeometry / NavIconStrokes）
│
├── shell/                       页面宿主与导航壳
│   ├── MainShell.kt             页面路由 + 命中层级顺序 + 组合各块
│   ├── ShellState.kt            OrbMode / BarMode / DetailStage + deriveBarMode（纯逻辑，可测）
│   └── orb/NongyuOrb.kt         星云球
│
├── login/
│   ├── model/                   LoginCenterUiState / LoginSessionState / VerificationPolicy
│   ├── session/                 LoginSessionHolder / SessionStartupVerifier
│   └── ui/                      LoginCenter / LoginFormBox / NebulaBackdrop
│
├── timetable/
│   ├── model/                   CourseEntry / WeekRange / ScheduleEntry / TimetableLimits
│   ├── logic/                   TimetableData / TimetableAxis / TimetableGeometry /
│   │                            CoursePalette / PeriodEnded
│   ├── data/                    CourseUserStore / CourseComments / TimetableMock
│   │   └── holiday/             HolidayParser / HolidayCache / HolidayFetcher
│   └── ui/                      TimetableScreen / Grid / Ruler / Toolbar / 各弹层 /
│                                WaterLine / WaterTilt / holiday/TimetableTitleBlock
│
├── skin/                        皮肤包（只依赖 design，不再依赖任何表现层）
└── net/                         网络层（见 网络层.md §2，本规格不重复）
```

**没有 `ui/` 这个中间包了。** 它是「什么都往里放」的温床：顶层包必须是一个
**单数、具名的能力域**（`login`、`timetable`、`skin`、`net`…），而不是按「是不是界面」
切一刀。新增顶层包需要先写 ADR 说明理由。

## 3 分层职责与可测性（这是分层的全部意义）

| 层 | 职责 | 能在哪测 | 硬约束 |
| --- | --- | --- | --- |
| `*/model/` | 数据结构、不变量 | **纯 JVM** | **禁止** import `android.*` / `androidx.compose.*`，**禁止**依赖本域其他层 |
| `*/logic/` | 纯函数、常量、几何换算 | **纯 JVM** | 同上；只允许依赖 `model/` |
| `*/data/` | 持久化、仓库接缝、网络抓取 | 部分纯 JVM（DataStore 需 Instrumented） | 可依赖 `model/` `logic/` |
| `*/ui/`、`shell/` | Composable | 编译期 + 真机验收 | 只允许依赖本域 `model`/`logic`/`design`，**禁止**直接 import 另一个域的 `ui` |
| `design/` | token、主题、通用零件 | 编译期 | **禁止**依赖任何业务域 |

依赖方向固定为：

```text
model ← logic ← data ← ui
design ← ui（所有 UI 都可以用 design，design 不认识任何业务）
```

### 3.1 `skin` 与 `design` 的依赖是单向的，不要退回去

`skin/` 需要 `NongyuColors` 这个**纯 `@Immutable data class`**（token 定义），
而 `design/Theme.kt` 需要 `SkinSource` / `SkinResolution` 来注入皮肤色板。
两者看起来像倒挂，实际**不构成环**：

```text
skin/  ──> design/NongyuColors.kt     （只用 token 数据结构）
design/Theme.kt ──> skin/SkinSource   （只做注入，唯一一处）
```

`skin/` 里**不得**出现对 `NongyuAppPlusTheme` / `LocalNongyuColors` / `NongyuTheme` /
`uiScaleFor` 的任何引用；`design/` 里除 `Theme.kt` 外**不得**出现任何 `appplus.skin` 引用。
两条都可以用 grep 一条命令核查。

### 3.2 已修正的倒挂（不要退回去）

| 曾经的问题 | 现状 |
| --- | --- |
| `skin/` import `ui.theme.NongyuColors` | 色板迁到 `design/NongyuColors.kt`，`skin` 只依赖 `design` |
| `model/CourseEntry` 的 `require` 依赖 `logic` 常量 | `PERIOD_COUNT` / `TOTAL_WEEKS` 下沉 `model/TimetableLimits.kt` |
| `logic/TimetableAxis`、`TimetableGeometry` 在 KDoc 里链到 `ui/` 的类 | 改成反引号文本，不再产生跨层编译依赖 |
| 屏宽自适应 `411f` + `coerceIn(0.85f, 1.25f)` 在两处各写一遍 | `design/UiScale.kt` 的 `uiScaleFor(widthDp)` |
| 登录会话状态机住在 `ui/login` | `login/session` + `login/model`，`ui` 只剩界面 |

## 4 `MainShell` 的边界（重要）

`MainShell` 允许持有：页面路由（`selectedTab`）、底部条形态与动画、命中层级顺序、
星云球状态、时间条与遮罩的置顶顺序。

`MainShell` **不允许**再增长：

- ❌ 业务数据读写（教师/地点/周次/考勤/备注的读、写、防抖落盘）→ 归 `timetable/data`，
  UI 侧用 `remember` 包装器持有；
- ❌ 纯判定逻辑（如「这节课是否已结束」）→ 归 `timetable/logic`，必须配单测；
- ❌ 形态推导的 `when` 顺序 → 归 `shell/ShellState.kt` 的 `deriveBarMode`，由单测锁定。

### 4.1 命中层级：改之前先看这张表

`MainShell` 里点击能否落到正确目标，靠的是 **Compose「后声明的先命中」**。
三张卡片（课程详情 / 日程明细 / 添加日程）的「点卡片外退出」层必须是**全屏 + 声明在底栏之前**：

```text
[后声明 = 先命中]
  输入栏 / 底部条（卡片本体住在这里，且更靠后）
  ...
  全屏 dismiss 层（点这里 = 点卡片外 = 退出）
[先声明 = 后命中]
```

历史上错两次：放在整屏最顶会连卡片内部一起吃掉；干脆不放则卡片外点了没反应。
**重构这段顺序时，必须真机验证「点课程盒子外部退出、点卡片内部不退出」。**

## 5 验证策略

| 改动类型 | 必须做 |
| --- | --- |
| 纯移动（包/文件搬迁） | `:app:compileDebugKotlin` + `:app:testDebugUnitTest` 全绿 |
| `model/` `logic/` `shell/` 纯逻辑 | 补对应单测（目前：`PeriodEndedTest`、`ShellStateTest`） |
| `shell/` 或任何 UI 行为改动 | 以上 + `:app:assembleRelease` + 真机四步（四 Tab / 球长按与点按 / 输入框展开收起 / 返键退出） |
