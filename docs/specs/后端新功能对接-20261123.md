## 2 三个关键契约差异（读代码核实）

### 2.1 二课的配方是**嵌套对象**，与 jiaowu 不同

| | jiaowu | secondclass |
| --- | --- | --- |
| 未命中形状 | `{code, address, method, cookies, ...}` **平铺** | `{code, message, recipe:{...}}` **嵌套** |

⇒ 不能复用 `CacheGetResponse`，单独建了 `SecondClassCacheResponse` + `SecondClassRecipeDto`。

### 2.2 响应信封每个端点都不一样

- `classrooms/lookup` → **平铺对象**（不是信封）
- `classrooms/buildings` → `{"items":[...]}`
- `classrooms/buildings/:id` → `{"data":{...}}`
- `post-reviews/*` → `{"items":[...],"next","query"}`（比普通帖子列表多 `query`）

### 2.3 `params_from` 是 snake_case

`SecondClassRecipeStepDto.paramsFrom` 必须写 `@SerialName("params_from")`，
否则 `ignoreUnknownKeys = true` 会**静默解析成 null**，不报错。

## 3 修复的两个真实缺陷

### 3.1 两个文件的 UTF-8 编码损坏（**我在 2026-11-17 那次提交引入的**）

`PostApi.kt`（94 处）与 `AnnouncementApi.kt` 存在**非法 UTF-8 字节**：
三字节字符被截断成两字节（如 `\xef\xbc\x88`「（」被截成 `\xef\xbc`）。

- 影响：`edit` 类工具直接拒绝读写；IDE 可能显示乱码但不一定报错
- 修法：整文件重写（逐处修补不可行，损坏点散布全文）
- **已全仓扫描确认清零**（`*.kt` / `*.xml` / `*.kts` / `*.pro` / `*.md` 全部可解码）

### 3.2 `AmapKeyRequest` 的默认值导致请求体为空

`suspend fun acquireAmap(body: AmapKeyRequest = AmapKeyRequest())` 配
`platform: String? = "amap"` 时，序列化结果是 `{}` ——
因为 kotlinx.serialization 的 **`encodeDefaults` 默认为 false**，带默认值的字段不序列化。

修法：`platform` 去掉默认值，强制调用方显式传。

> 这与 `CasBodies.kt` 里 `CasSmsSendBody.type` 的记录的是同一条教训。

## 4 三个「假差异」记录（避免下次重复排查）

| 现象 | 真相 |
| --- | --- |
| 客户端有 `/school/presence`，后端「没有」 | 后端用常量 `presenceRoute` 注册，正则只匹配字面量路径 → **误报**，presence 正常 |
| 客户端有 `/announcements/latest`，后端「没有」 | 后端把 `latest` 做成 `:id` 的特例（同一路由），不是并列注册 → **正常** |
| 大量路由「两边都不匹配」 | 路径参数占位符写法不同（`:id` vs `{id}` vs `:p`），未经归一化直接比较 → **误报** |
