## 3 ⚠️ 规格 §8.3 的假设被证伪

规格 §8.3 写：

> **删掉 `RetrofitSpikeProbe.kt`，是让 R8 结论从「空洞的成功」变成「真实数据」的前提条件。**

**实测：删掉之后，R8 仍然把整条库链删光了。**

```
=== mapping.txt 保留类数 ===
okhttp3                  kept=0
retrofit2                kept=0
kotlinx.serialization    kept=0

=== usage.txt 移除行数 ===
okhttp3                  removed_lines=326
retrofit2                removed_lines=120
kotlinx.serialization    removed_lines=364
```

### 为什么

R8 从**入口点**（`MainActivity` / Manifest 声明的组件）出发做可达性分析。
删掉探针之后，网络层确实变成了一套真实实现，但**没有任何业务代码引用它** ——

```
=== 网络层之外的文件是否引用 net ===
（空）
```

`MainActivity` 的 import 只有 `skin.FileSkinSource`、`ui.NongyuApp`、`ui.theme.*`。
所以 `NetHolder` / `NongyuApi` 及其下游在 R8 眼里**整体不可达**，连编译产物都不进 APK。

### 结论修正

- **删除探针 ≠ R8 结论变真**。真正的充要条件是「**有业务代码从入口点可达地引用网络层**」。
- 一期（#50 Q6 = 网络层不接 UI）**在结构上就不可能**满足这个条件。
- 因此：**R8 keep 需求在一期无法验证**，这一条应继续挂在待实测清单，直到网络层被真实接入。

### 已同步到规格

`docs/specs/网络层.md` §8.3 与 §10.2 均已加注这条修正。原来那句「删探针就能测出 R8」的话被保留但标注为**已证伪**，避免后来人重走一次。

## 4 其它发现

### 4.1 `netLoggingEnabled()` 也必须按源集两写

初版想在 `NetHolder` 里用运行时判断决定是否挂日志拦截器，但这与规格 §6.3「结构性隔离、不用 `BuildConfig.DEBUG`」冲突。
改为 `src/debug` 与 `src/release` 各写一份（与 `NetConfig` / `DefaultTokenProvider` 同一手法）。

### 4.2 `errorBody` 解析必须容错，否则 404 会被误分类

`backend-plus` 在无 DB 时**不注册** `/identity/me` 等路由，返回的是 **`text/plain` 的 404**。
若 `NetJson.parseErrorEnvelope` 对非 JSON 抛异常，`ApiCall` 的 `Throwable` 兜底会把它归成
`ApiFailure.Parse` —— 一个本该是 `Http(404)` 的分类错误。

已在 `NongyuApiE2ETest.404 text-plain 归 Http 而不是 Parse` 中固化这条。

### 4.3 空壳测试要删掉，不要留着凑数

初版 E2E 测试里有一个 `鉴权端点带上 Bearer 头`，实际什么都不断言（`assertTrue(api is NongyuApi)` 恒真）。已删除 —— 留一个恒真的测试比没有测试更糟，它会让人以为覆盖了。
