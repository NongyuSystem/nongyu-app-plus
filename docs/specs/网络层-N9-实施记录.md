## 2 交付清单

### 新增接口方法（`net/api/IdentityApi.kt`）

| 方法 | 路径 | DTO |
| --- | --- | --- |
| `login(body)` | `POST /identity/login` | 请求 `LoginRequestDto` → 响应 `LoginDto` |
| `logoutAll()` | `POST /identity/logout/all` | `LogoutAllAckDto`（`ok` + `revoked`） |
| `status()` | `GET /status` | `StatusDto`（5 个依赖字段） |

三者都标了 `@PublicEndpoint` 中只有 `login` / `status` / `healthz` 是公开端点；
`logoutAll` 需 Bearer。

### 新增 DTO（`net/model/IdentityDto.kt`）

- `LoginRequestDto` —— 四种登录方式共用一个 DTO，字段全可空 + 默认 `null`。
  `school` 方式主力字段是 `goAdminTgt`；`xsgzToken` 可选（后端自己用 tgt 换）。
- `LogoutAllAckDto` —— 与 `LogoutAckDto` 分开（`{"ok":true,"revoked":n}` vs `{"ok":true}`）。
- `StatusDto` —— `process` / `postgres` / `redis` / `breaker` / `storage`，全可空。

### 新增错误码（`net/core/ApiErrorCode.kt`）

`app_sign_invalid`（401）/ `app_sign_too_large`（413）/ `app_sign_unavailable`（503），
并登记进 `KNOWN`。文档 §1.4：这三者的错误形状是 `{"code":"..."}`，**无 message**。

### ⚠️ 行为修正：签名豁免路径（`net/http/AppSignInterceptor.kt`）

**这是本轮唯一的行为改动，不是纯补全。**

文档 §1.4 明写：**仅 `/healthz`、`/status` 免签名**，其它一切请求都要签名，
「登录、发验证码这些公开路径**也要签名**」。原实现对**所有**请求签名（含探针），
与契约不符。

修正：`AppSignInterceptor` 用 `encodedPath` **精确匹配**豁免集合 `setOf("/healthz","/status")`，
命中则直接 `chain.proceed(request)` 不挂签名头。用精确匹配而非前缀，防止
`/healthz/extra` 之类被误豁免。

同时澄清两套概念（已写进 `PublicEndpoint` KDoc）：

| 概念 | 由谁决定 | 效果 |
| --- | --- | --- |
| **公开**（`@PublicEndpoint`） | 客户端 | 不挂 `Authorization: Bearer`，无 token 也照发 |
| **免签名** | 后端 appSign 中间件 | 只有 `/healthz`、`/status` |

**「公开」≠「免签名」**。后端签名中间件在用户鉴权之前，登录端点公开但仍要签名。

## 3 顺带修好的一个既有测试

`AppSignInterceptorTest` 第一条用例用**裸 OkHttp Request** 打 `/identity/login/admin`，
且 `tokenProvider` 返回 `null`。因为裸请求没有 Retrofit 的 `Invocation` tag，
`AuthInterceptor` 把它判成「需鉴权端点」并短路，抛 `MissingCredentialException`。

这不是本轮改动引入的回归（未动 `AuthInterceptor`），而是测试前提与新契约不符。
修法：给该用例一个非空 token（它测的是签名头与 body 完整性，token 不是被测对象），
并在注释里说明「裸请求带不了 `@PublicEndpoint` 注解」。
