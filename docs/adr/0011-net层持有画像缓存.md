# ADR-0011 `net` 层持有画像缓存

- 状态：已采纳（2026-11-26，票 #112 / 规格 #111）
- 相关：ADR-0008、`docs/specs/网络层.md`、`docs/specs/网络层-N2-N5-实施记录.md`、`docs/adr/0006-冷启动只读本地皮肤包不碰网络.md`

## 背景

「个人」Tab 过去一片空白：客户端把登录响应里的 `user` 拿到就丢，启动校验打一次
`GET /identity/me` 却只判成败、响应体直接丢弃，本地一个字都没存。

两份数据是互补的，谁都不能单独满足页面：

- 登录响应有姓名/学号/班级/专业/年级与 `expiresAt`，**没有头像与 QQ**；
- `/identity/me` 有头像与 QQ，**没有学号**（Go `omitempty` + 构造处不填）。

后端无 DB 时 `/identity/me` 路由不注册，返回纯文本 404 而非 JSON；首次失败后如果只靠
`/me` 填缓存，页面会永久空着。

## 决策

### 1. 缓存归属 `net` 层，与会话存储并立

新增 `net/profile/ProfileStore`，与 `net/auth/SessionStore` 同级、同风格：

- DataStore 落盘 + `ReplaceFileCorruptionHandler` 损坏容错（真机踩过 `CorruptionException`
  是 `IOException` 子类，只 catch `RuntimeException` 会漏）；
- 构造只存 context，首次读写才碰磁盘（不违反 ADR-0006 冷启动守卫）；
- **只存画像，绝不存凭证**：令牌真源仍只有 `SessionStore` 一个；
- `NetHolder.profileStore(context)` 惰性 getter 暴露给装配点，**不进 `NongyuGateWay`
  的门面方法清单**（门面 KDoc 写明只暴露明确列出的方法）。

编解码与「文件损坏 → 视为无缓存」判定放纯逻辑类 `profile/logic/ProfileCodec`，
Android 侧 DataStore 只做存储适配；这样容错行为可在纯 JVM 单测中锁死。

### 2. 唯一 `/me` 出口顺手落盘，页面零请求

`NongyuGateWay.me()` 是**全仓唯一打 `/identity/me` 的地方**（启动校验
`SessionStartupVerifier` 本来每进程就会调一次）。在它返回 `Success` 时顺手把
`ProfileDto` 写入画像缓存。登录链路的 `NongyuGateWay.login()` 同理，把此前被丢弃的
`LoginDto.user` 落盘。

页面自身**不发** `/me` 请求，只读本地缓存实现「本地优先」：

- 请求次数不变（仍是一次启动校验 + 一次登录）；
- 启动校验判定逻辑（`VerificationPolicy.decide` / `applyResult`）**一字不动**；
- 即使 `/me` 失败，登录响应兜底的姓名/学号仍在缓存里，页面不空白。

### 3. 落盘失败绝不影响登录判定

`ProfileStore.read/write/clear` 内部吞掉 `IOException` / `RuntimeException` 并返回
默认值；`NongyuGateWay` 的 `cacheProfileQuietly` 再兜一层：落盘抛任何异常都只记日志、
不冒泡。门面方法（包括 `me()` 与 `login()`）的返回值只由网络结果与 `ApiCall` 分类决定，
**缓存写失败绝不能把正常登录判成会话过期**（规格 US24）。

## 后果

- 新增 `profile` 顶层能力域（`model / logic / data / ui`，`model`/`logic` 禁 import
  Android/Compose），与 `net/profile` 存储适配；符合 ADR-0008。
- 画像数据的三态推导、两份数据合并优先级、缓存非空判定都是 `profile/logic` 纯函数，
  纯 JVM 单测覆盖易错的 `when` 顺序与字段缺失组合。
- 若将来启动链路不再打 `/me`（例如改成登录后显式拉取），本「顺手落盘」设计失效，
  画像页必须自己请求 —— 届时需在页面加显式拉取并重新评估请求次数。
- demo 数据放 `app/src/debug`（结构性差异，release 零污染），**不放** `src/test`
  （纯 JVM 源集不进 APK runtime classpath）。
