# 冷启动只同步读本地皮肤包，不碰网络

皮肤包与色值接口都还没实现，而启动路径几乎是空的（`MainActivity.onCreate` 只有 `enableEdgeToEdge()` + `setContent`，色板是编译期默认参数）。往里插入任何 IO 都是**净增成本**，所以定位必须是「读本地已校验的包」，而不是「顺手联网检查更新」。四个决定：冷启动同步读本地、两载体各自判定逐项回落、失败静默记日志、不跳色且 TTFD 只算首帧。

## Status

accepted（2026-11-08，维护者在 wayfinder #28 拍板）

## 决策内容

| 项 | 结论 |
| --- | --- |
| 启动路径 | **冷启动只读本地、绝不碰网络**（Q1=B）：同步读 `filesDir` 里「当前指针」指向的**已校验**包，首帧即正确皮肤；**不做版本比对、不检查是否有新版**。网络检查 / 下载全部放到首帧之后 |
| 两载体版本 | **各自独立判定 + 逐项回落**（Q2=C）：色值（数据库目录接口）与资源（皮肤包）各自按自己的 `minAppVersion` 与 schema 版本通过 / 拒绝；不一致不视为错误，界面按 #23 的三层降级与 #25 的逐资源回落处理 |
| 失败表现 | **静默回落内置默认 + 记日志**（Q3=B）：不新增任何用户可见提示（本期无设置页，提示无处安放），与 #24 Q2 的「未知 token 记日志」一致 |
| 跳色 | **不允许首帧后跳色**（Q4=A）：换皮只在下次启动生效，首帧永远正确 |
| TTFD | **只算到首帧**（Q4=X）：换肤完成不计入可交互时间，避免把异步就绪混进启动指标造成失真 |
| 内置兜底 | 复用 #23 已定的「**一整套可用默认皮肤**」，本决策不重定最小集 |

## Considered Options（被否掉的备选）

| 备选 | 否决理由 |
| --- | --- |
| 完全不碰本地包，首帧用旧皮肤或默认 | 换皮要等下次启动才生效、且首帧是旧皮肤，体验上像 bug；而读本地磁盘的成本远低于网络 |
| 启动期允许同步网络请求 | 与官方口径直接冲突（上游 #22：`setKeepOnScreenCondition` 不授权启动期网络 IO；网络 / 磁盘 IO 属要移出启动路径的典型问题），弱网下可能白屏 |
| 两载体不做任何一致性约束（各自乱用） | 会放任「新配色 + 旧图标」的混搭且无任何收敛机制 |
| 引入共同的「皮肤版本」对两载体兜底 | 等于给已分家的两个载体再造一个共同版本号，与 #24 Q1=C 的方向相反 |
| 失败时弹提示 | 本期无设置页，没有提示的安放位置 |
| 允许跳色并加过渡动画 | 每次换皮都会触发 `staticCompositionLocalOf` 的**全树重组**（#24 Q3=B 已记代价）；为一次换肤付整树重组不划算 |
| 换肤完成才计入可交互时间 | 会让启动指标失真 —— 皮肤的异步就绪不属于「App 可交互」的必要条件 |

## Consequences

- **启动路径增加一次磁盘读**：读「当前指针」+ manifest + 本次需要的资源文件。这是**净增成本**，必须在 #26 的基线上量出来；若量出明显劣化，回落方案是「指针读失败或包缺失就直接用内置默认，不重试」。
- **换皮感知延迟 = 一个启动周期**：B 方案下用户下载完新皮肤，下次打开才看到。这是刻意的取舍，换掉了「首帧跳色 + 全树重组」。
- **两载体天然可能版本不一致**：Q2=C 承认这个既成事实（#24 Q1=C 的后果），只在渲染层各自回落，不试图把它们对齐。规格里需要分别记录两者的「当前生效版本」以便日志排查。
- **失败静默的代价**：用户不会被告知「皮肤没换成」。因此日志必须写清楚是哪一环失败（无包 / 校验失败 / schema 过高 / minAppVersion 过高），否则排查只能靠猜。
- **与 #31 的关系**：「冷启动不碰网络」这条**直接成为整体优化的约束条件** —— #31 定度量口径与瓶颈排序时，任何把网络拉回启动路径的方案都与本决策冲突。
- **SplashScreen 保持条件**：#26 已接 `core-splashscreen`，其 `setKeepOnScreenCondition` 只允许等「少量本地数据、求值要快」，与本决策（只读本地）相容；**不得**用它去等网络。
