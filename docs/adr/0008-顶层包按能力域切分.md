# ADR-0008 顶层包按能力域切分，不再有 `ui/` 中间层

- 状态：已采纳（2026-11-12）
- 相关：`docs/specs/界面层.md`、`docs/specs/网络层.md §2`

## 背景

界面代码一度全部住在 `com.nongyu.appplus.ui` 下（37 个文件、8,511 行，占 main 的 62%），
而这个包没有对应的结构规格：`net/` 有 `网络层.md §2` 的分层表与可测性表，`skin/` 有
ADR-0003~0006，唯独界面层只靠「往 ui 里放」这一条约定。

后果是可验证的：

- `ui/MainShell.kt` 长到 1,392 行，单个 Composable 函数 1,129 行，36 个状态、16 个 `LaunchedEffect`；
- 纯数据模型 `CourseEntry` 的 `require` 反向依赖 `logic/` 的常量；
- 业务数据读写（教师/地点/周次/考勤/备注 + DataStore 防抖落盘）堆在导航壳里，0 测试；
- `skin/`（数据源）反向 import `ui.theme.NongyuColors`（表现层）。

## 决策

**顶层包必须是一个单数、具名的能力域**，包内按 `model / logic / data / ui` 分层；
不再存在按「是不是界面」切出来的 `ui/` 中间包。

依赖方向固定：

```text
model ← logic ← data ← ui
design ← ui（design 不认识任何业务域）
```

新增顶层包需要先写 ADR 说明理由；包内分层由 `docs/specs/界面层.md §3` 的可测性表约束，
其中 `model/` 与 `logic/` **禁止** import `android.*` 与 `androidx.compose.*`。

## 后果

- `skin/` 与 `net/` 的形状被推广到界面层，三处范式一致；新人从目录就能判断
  「这个文件能不能纯 JVM 测」。
- 纯逻辑（考勤判定、底部条形态优先级）第一次有了单测（`PeriodEndedTest`、`ShellStateTest`）。
- 代价：一次大范围搬家让 `git blame` 在搬家提交处断代；已用「纯移动、无行为变更」
  的独立提交把影响隔离，`git log --follow` 仍可追溯。
- 遗留：`shell/MainShell.kt` 仍偏大，后续继续拆；见 `界面层.md §6`。
