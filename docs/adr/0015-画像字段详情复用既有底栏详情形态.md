# ADR-0015 画像字段详情卡复用既有底栏详情形态，不新增形态值

- 状态：已采纳（2026-11-26，票 #113 / 规格 #111）
- 相关：ADR-0008、`docs/specs/界面层.md` §4.1、ADR-0011

## 背景

票 #113 要求点击画像字段进入详情卡，可复制、可上滑或点外部退出。界面层规格
§4.1 写着「第 3 个变形页触发 `BarSlot` 重构」，而画像字段详情恰好会是第三个
变形页。规格 #111 的 Implementation Decisions 明确要求**有意绕开**这条触发线：
画像详情复用既有底栏 `BarMode.Detail` 的高度与退出语义，不新增底栏形态枚举值。

代码核查（`.dsh-tmp/worktrees/UI-SEAMS.md`）显示：穷尽 `when(barMode)` 的地方不止
`deriveBarMode`，还有 `BarHeight.barTargetHeight`、`barCorner`、点击消费、占位上报、
`OrbHost.enabled` 等 6–8 处；新增枚举值会牵动尚未完成的 `BarSlot` 重构。

## 决策

**复用 `BarMode.Detail` 形态，用两个互斥的可空状态表达卡片内容：**

- `MainShell` 持有 `detailCourse: CourseEntry?` 与 `profileDetailField: ProfileFieldItem?`；
- 二者互斥：打开画像字段详情前先清 `detailCourse`，反之亦然；
- `deriveBarMode(hasDetailCourse = detailCourse != null || profileDetailField != null)`
  仍返回 `BarMode.Detail`——高度、圆角、点击消费、动画全部沿用既有实现；
- `AnimatedContent` 的 `BarMode.Detail` 分支内先判 `profileDetailField`，有则渲染
  `ProfileFieldDetailContent`，否则才渲染课程 `DetailCardContent`；
- 收拢动画走完时两个状态一起清，点外部 / 上滑越过阈值都走同一个 `collapseDetail()`；
- 上滑阈值判定下沉为纯函数 `ProfileFields.dismissByDrag`，纯 JVM 单测锁定；
- **不新增 `BarMode` 枚举值，不改动 `BarSlot` 相关清单。**

## 后果

- 画像详情与课程详情不可能同屏；一门课的详情正开着时点画像字段会切换内容，
  不会叠加两个卡片。
- 若将来真机验证发现两套内容的高度诉求无法共存（例如画像详情需要独立三档），
  则退回界面层规格 §4.1 的逐项改动清单，新增枚举值并同步更新形态计数。

## 验证

- `ProfileFieldsTest` 锁定字段取舍、复制文案、详情标题、退出目标、拖拽阈值；
- 编译与 assembleRelease 保证 `when(barMode)` 全分支仍穷尽、无新增形态值；
- 真机四步验收（点字段进详情 / 复制 / 上滑退出 / 点外部退出）留待有设备时人工执行。
