# 色值通道走数据库目录接口，色板容器改用 staticCompositionLocalOf

色值要在不发 APK 的前提下可换，但「色值实体」到底跟着皮肤包走、还是由数据库单独发，两条路会决定版本协商、缓存与校验要写几套。维护者拍板：**由数据库提供「当前指针 + 色值段」的目录接口**，客户端从同一 HTTP 接口取；皮肤包契约退守到「资源载荷」。同时 `LocalNongyuColors` 从 `compositionLocalOf` 改为 `staticCompositionLocalOf` —— 本期没有运行时换肤入口（无设置页、无偏好标识），色板只在冷启动读包时定一次，正合官方「值几乎不会变就用 static 拿性能收益」的口径。

## Status

accepted（2026-11-08，维护者在 wayfinder #24 拍板）

## 决策内容

| 项 | 结论 |
| --- | --- |
| 色值下发载体 | **数据库目录接口**（维护者选 Q1=C）：服务端在数据库里存「当前指针 + 色值段 JSON」，客户端从同一 HTTP 接口取，由服务端拼装后返回。**不走皮肤包的 `colors` 段** |
| 皮肤包契约的收窄 | `docs/adr/0003` 的「两条载荷通道」收缩为：**资源载荷仍随包**（图标/字体），**色值载荷改由目录接口承载**。manifest 的 `colors` 段标记 **deprecated**（字段保留、客户端忽略），物理删除留到 `/to-spec` |
| token 必填性 | **分两档**（Q2=C）：**核心 5 项必填** —— `colorBrand`、`colorBackground`、`colorCard`、`colorText`、`colorIndicator`；其余 11 项可选、缺则沿用内置默认。**必须记日志**：未知 token 名、缺失的核心 token，否则宽松规则会退化成静默失效 |
| 运行时替换机制 | `LocalNongyuColors` 改 **`staticCompositionLocalOf`**（Q3=B）；换肤仍只换传给 `NongyuAppPlusTheme(colors=…)` 的对象，Composable 层零改动 |
| 解析库 | **平台自带 `org.json`**（Q4=A），零新增依赖、零版本风险 |
| 偏好标识 | **本期不做**（Q5=A）：全局单指针说了算，客户端不存「用户选了哪套」 |

## Considered Options（被否掉的备选）

| 备选 | 否决理由 |
| --- | --- |
| 色值随皮肤包清单走（我起草时的建议 A） | 与维护者的选择相反。它能让「一套下载链路」成立，但把「换配色」与「改图标」绑成一次发布 |
| 色值独立走数据库、资源包也独立一套契约 | 会完全退回 #23 已否决的「两套契约」形态 |
| `compositionLocalOf`（ADR 0002 原选择） | 本期色板只在冷启动定一次、无运行时切换入口，官方口径是「值几乎不会变就用 `staticCompositionLocalOf` 拿性能收益」；`compositionLocalOf` 的读追踪收益在本期用不上，反而每次读都带开销 |
| 引入 `kotlinx-serialization` | 其 `.module` 要求 `kotlin-stdlib` ≥ 2.3.21，本仓 Kotlin 2.3.0；要用就得升 Kotlin（动构建） |
| 做设备级偏好 / 接后端 `user_settings.theme` | 既无 UI 写入点，其枚举（`sicau_green`/`sakura_pink`/`dark`/`system`）与 `packId` 也不是一套标识 |

## Consequences

- **Q1=C 的代价要说清**：色值与资源分开承载后，就出现「两个载体、两个版本」的可能 —— 数据库说 v5、皮肤包停在 v4。这条**不由本 ADR 解决**，归 [皮肤下发与冷启动的交叉约束](https://github.com/NongyuSystem/nongyu-app-plus/issues/28)（该票第 4 点正是「两通道就绪时机不一致时的降级粒度」）。
- **ADR 0003 需同步收窄**（已在本轮补 amend 说明）：它写的是「一份清单 + 一条下载链路、两条载荷通道各自可为空」。Q1=C 之后，色值载荷不再随包，那条「两条载荷通道」只剩资源那一条实际在用。
- **ADR 0002 需同步 amend**：它记录的是 `compositionLocalOf`，Q3=B 改为 `staticCompositionLocalOf`。已在其 Status 补注，不重写原文。
- **`staticCompositionLocalOf` 的代价**：它的读取不被 Compose 追踪，**换值会让提供处的整块 content 重组**。本期可接受（色板只在冷启动定一次）；但若将来做「运行时切换皮肤」，这里会变成一次全树重组，需要重新评估。
- **核心 5 项是强约束**：B 端漏发 `colorBrand` 之类核心色，整份色值段按非法处理、回落内置白绿，并记日志；非核心缺失只逐项回落。
- **`org.json` 的代价**：无类型安全，16 个字段靠手写取值 + 校验。规模可控，但解析代码需要单元测试兜住。
