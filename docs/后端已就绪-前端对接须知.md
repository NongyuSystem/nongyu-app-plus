## 2. NY1 请求签名（必做，否则全 401）

### 2.1 四个头

| Header | 值 |
| --- | --- |
| `X-Nongyu-Key-Id` | `dev`（当前环境的 kid） |
| `X-Nongyu-Timestamp` | Unix 秒，字符串 |
| `X-Nongyu-Nonce` | 16 字节随机，base64url 无 padding |
| `X-Nongyu-Signature` | `base64url(HMAC-SHA256(key, canonical))`，无 padding |

### 2.2 规范化串（逐字节，末尾必须有 `\n`）

```
NY1\n
<keyId>\n
<unixSeconds>\n
<nonce>\n
<METHOD 大写>\n
<escapedPath>\n
<rawQuery>\n
<lowercase-hex SHA-256(body)>\n
```

- `escapedPath`：OkHttp 用 `request.url.encodedPath`；JS 用 `encodeURI` 处理后的 path
- `rawQuery`：无 query 时是**空串**，不是 null
- `body`：原始字节的 SHA-256 小写 hex；GET 无 body 用空字节数组

### 2.3 客户端已有实现

`app/src/main/java/com/nongyu/appplus/net/sign/AppRequestSigner.kt` + `net/http/AppSignInterceptor.kt`，**已与后端逐字节对齐**，不需要改。

开发密钥（`AppRequestSigner.DEV_KEY_ID` = `dev`）与后端 `.env` 里的是同一把，非生产秘密。

### 2.4 失败形态

```json
{"code":"app_sign_invalid"}   // 401，缺头/格式错/kid未知/时间戳越窗/签名不符/nonce重放
{"code":"app_sign_too_large"} // 413，body > 1MiB
{"code":"app_sign_unavailable"} // 503，nonce 存储不可用
```

**注意：这三个响应只有 `code`，没有 `message`。**

## 3. 从零注册：只能走 school 登录

### 3.1 请求

```
POST /identity/login
Content-Type: application/json
```

```json
{
  "method": "school",
  "deviceId": "设备唯一标识",
  "goAdminTgt": "201690:TGT:xxx",
  "xsgzToken": "可选，不传后端自己换"
}
```

**必须带 `goAdminTgt`**（我新加了校验）：

- 它必须是**合法 tgt 值**，形态 `201690:TGT:<base64url>`，约 55–60 字符
- **不能是 HTTP 响应的 body**。这是个真实踩过的坑：客户端把 302 重定向返回的 HTML
  （`<a href="https://webvpn.sicau.edu.cn/login">Found</a>.`）当成 cookie 值交上来，
  后端存进 Redis 后每次换票都 500 未登录，表现为「能登录但画像全空」
- **正确取法**：从登录响应的 `Set-Cookie` 头里提取 `go-admin-tgt` 的值

后端也会校验：长度 8–512、含 `:`、纯可见 ASCII、不含 `<>"'\\` 与空白。不合法会返回 400 `invalid_request`。

### 3.2 成功响应

```json
{
  "token": "<会话令牌>",
  "expiresAt": 1765000000,
  "isNew": true,
  "profileIncomplete": false,
  "user": {
    "id": 1,
    "studentNo": "202500001",
    "name": "张三",
    "college": "信息工程学院",
    "major": "数据科学与大数据技术",
    "className": "大数据202503",
    "grade": "2025"
  }
}
```

- `expiresAt` 是 **Unix 秒整数**（不是字符串）
- `isNew: true` 表示这次建了号
- `profileIncomplete: false` 表示学工档案已完整落库

### 3.3 后端在登录时做了什么（前端不用管，但理解有帮助）

```
goAdminTgt → 换 st+userId → 换 access token → checkUserAndGetUserLevel
           → enterHall → student/detail → 落库 4 张表
```

如果取档案失败，**登录仍然成功**（拿到姓名+学号），但 `profileIncomplete` 会是 `true`，
且 `college/major/className/grade` 为空。此时后端日志会出现
`学工取数链路失败` 的 WARN —— 让后端去查，前端不要重试。

## 4. 其余登录方式（都只能登录，不能建号）

| method | 需要字段 | 账号不存在时 |
| --- | --- | --- |
| `password` | `studentNo` + `password` | 400 `need_school_auth` |
| `mailcode` | `email` + `code` | 400 `need_school_auth` |
| `idcard` | `studentNo` + `idCardSuffix4` + `nameInitials` | 400 `need_school_auth` |

`need_school_auth` 的正确 UI 处理：提示「该账号尚未注册，请先完成学校认证登录」，引导回 `school` 方式。

发验证码：`POST /identity/mailcode/send`，body `{"email":"..."}`。
返回 400 可能是邮箱格式错，**429 是发送太频繁**（需节流，别连续点）。

## 5. 字段校验（我新加的，前端要知道）

下面这些不合法会返回 **400 `invalid_request`**（响应体只有 code，无 message）：

| 字段 | 规则 |
| --- | --- |
| `method` | 必须是 `school` / `password` / `mailcode` / `idcard` |
| `studentNo` | **9 位数字** |
| `password` | 非空，≤256 字符 |
| `email` | 必须含 `@` 与域名点号，≤254 |
| `code`（mailcode） | **4–8 位字母或数字** |
| `idCardSuffix4` | **4 位数字** |
| `nameInitials` | 只含字母/空白，≤64 |
| `deviceId` | ≤128 |
| `goAdminTgt` | 见 §3.1 形态规则 |

PATCH `/identity/me/profile`：`qq` 只能纯数字（≤32）；`avatarUrl` 必须是绝对 http/https URL（挡 `javascript:`/`data:`）。

`POST /school/login` 需要 `code` + `uuid`，两者都必填且非空白。

## 7. 会话与错误码

| 项 | 值 |
| --- | --- |
| App 会话 TTL | 30 天，**不滑动续期** |
| 管理台 TTL | 12 小时 |
| 单设备 | 是，新登录会踢掉旧的同 scope 会话 |
| 鉴权头 | `Authorization: Bearer <token>`，大小写敏感、单个空格 |

**错误响应形状两种并存**：

- identity / 中间件 / 签名：`{"code":"..."}` —— **没有 message**
- school 域：`{"code":"...","message":"..."}`

未匹配路径返回 gin 默认 `text/plain` 的 `404 page not found`，不是 JSON。

常见码：`unauthorized`、`session_expired`、`bad_credentials`、`need_school_auth`、
`forbidden`、`user_disabled`、`rate_limited`、`internal_error`、`invalid_request`、
`app_sign_invalid`。

## 8. 联调自检清单

1. 打 `/healthz` → 应 200，**不需要任何头**
2. 打 `/announcements` 不带签名 → 应 **401 `app_sign_invalid`**（证明签名层生效）
3. 带齐 4 个签名头再打 `/announcements` → 应 200（空列表）
4. `POST /identity/login` 带签名 + 真实 `goAdminTgt` → 应 200，`isNew: true`
5. 用返回的 token 打 `/identity/me` → 应 200，`college/major` 应**有值**
6. 同一个 nonce 用两次 → 第二次 401（重放防护）
7. 时间戳偏移 > 5 分钟 → 401

**第 5 步是关键验收点**：如果 `college/major` 为空但 `name` 有值，
说明这次登录的 `goAdminTgt` 又有问题（不是合法 tgt 值），去看后端日志的
`学工取数链路失败` WARN。
